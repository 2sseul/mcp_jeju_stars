## 0. 한 줄로

서버 코드는 한 줄도 건드리지 않고 **LLM 이 읽는 도구 설명 문자열만** 구조화해서,
같은 모델·같은 24케이스에서 **인자 슬롯 F1 0.862 → 0.961**, **환각 수치 1.4% → 0.0%**,
**지도 주소 전달 95.0% → 100.0%**, **근거 재현 83.1% → 87.3%** 로 올렸다.
도구 선택 정확도·과잉호출은 **원래도 100% / 0%** 라 유지가 목표였고, 유지했다.
치른 값은 프롬프트 토큰 **6,735 → 9,708 (+44%)** 이고 지연은 사실상 그대로다
(t_e2e 중앙값 4.26s → 4.09s).

## 1. 왜 설명을 건드렸나

1차 측정에서 **같은 서버·같은 도구인데 모델에 따라 도구 선택 정확도가 18.1% ~ 100% 로
갈렸다** (`gemma4:e2b-it-qat` 18.1% · `llama3.1:8b` 66.7% · `qwen3.5:4b` 100.0%,
원자료 [results/raw_old_prompt/](results/raw_old_prompt/)). 서버는 하나인데 결과가
이렇게 갈린다면 고칠 자리는 서버 로직이 아니라 **LLM 과 서버 사이의 계약 — 도구 설명**이다.

그래서 2차부터 범위를 좁혔다. **모델은 `qwen3.5:4b` 하나로 고정하고, 바꾸는 것은
설명 문자열뿐이다.** 하네스가 스키마의 `description` 만 갈아 끼우므로
([harness.py:167](harness.py#L167)) 판정 로직·응답 형식·시스템 프롬프트는 전 판본이 동일하다.
차이는 오직 설명에서 온다.

## 2. 어떤 방법을 썼나

### 2.1 적용한 여섯 기법

기존 설명(V0)은 사람이 읽는 산문이었다. 이것을 **에이전트가 읽는 계약**으로 다시 썼다.
저장소 안에서는 이 묶음을 머리글자를 따 **MAID**(Mission · Arguments · Interactions ·
Diagnostics · Examples)라고 부른다 — 논문의 이름이 아니라 이 저장소에서 붙인 이름이다.

| # | 기법 | 이 서버에서 무엇을 했나 |
|---|---|---|
| 1 | **의도 명확화** (Mission) | 도구마다 `[언제]` · `[다른 도구와]` · `[사전 조건]` 세 줄. 특히 "**인자를 하나도 안 줘도 부를 수 있다**"를 명시해 되묻기를 없앴다 |
| 2 | **인자 타입 주석** (Arguments) | 형식 · 허용값 · 기본값 · 예시를 인자 설명에 인라인 (`region` 은 다섯 값뿐 · `time` 은 `HH:MM` · "밤 10시" → `22:00`) |
| 3 | **상호작용 명세** (Interactions) | `[다음]` — 이 도구 뒤에 어떤 도구를 부르는가 |
| 4 | **에러 응답 명세** (Diagnostics) | `[오류 대처]` — 실패 모양별로 다음 행동. "주소 확인 실패면 좌표로 다시" · "`spots` 가 비면 조건을 하나만 풀어 다시" |
| 5 | **사용 예시** (Examples) | `[예시]` — 질문 → 호출 인자 3쌍. **호출 인자까지만** 든다(§6.3 참조) |
| 6 | **검색 친화 키워드 + 경계** | 첫 줄에 동의어를 몰아 두되(추천·찾기·어디로 갈까 / 별 보여?·괜찮아? / 주차·강아지·야간 출입), **반드시 `[부르지 않는 경우]` 절과 짝으로** 넣는다 |

기법 6의 뒷부분(경계)이 이 실험의 핵심 발견이다. §6.1 을 보라.

### 2.2 판본 계보

| 판본 | 무엇 | 파일 | 결과 |
|---|---|---|---|
| **V0** | 기존 산문 설명 = **baseline** | `modules/routes.py` (당시) | 비교의 분모 |
| **V1** | 기법 1~5 + 키워드 증강 | [tool_desc_v1.py](tool_desc_v1.py) | 인자는 좋아지고 **과잉호출이 터졌다** |
| **V2** | V1 + 경계 명시 | [tool_desc_v2.py](tool_desc_v2.py) | **채택 → 운영 반영** (커밋 `e56927a`) |
| **V3** | V2 + 오류 표 구조화 + 인자 3축 라벨 | [tool_desc_v3.py](tool_desc_v3.py) | **판정 보류** (§7) |

지금 `modules/routes.py` 에 들어 있는 설명이 V2 다. 그래서 이후 측정의 `--variant v0`
(= 서버가 주는 설명)은 사실상 V2 를 가리킨다.

## 3. 어떤 문헌의 어떤 방법론인가

> **밝혀 둘 것.** 이 저장소의 초기 주석은 출처를 "MCP Tool Description 최적화 ·
> arXiv 증강 도구 설명" 이라고만 적어 두었고 논문 제목·식별자를 남기지 않았다.
> 아래 표는 **적용한 기법마다 그 기법을 실제로 제안·검증한 문헌**을 되짚어 붙인 것이다.
> 모두 실재를 확인한 문헌이다. 인용문을 그대로 옮겨 쓸 때는 원문을 다시 확인할 것.

| 이 저장소의 기법 | 근거 문헌 | 그 문헌의 방법론 | 그 문헌이 보고한 개선 |
|---|---|---|---|
| 설명 최적화라는 접근 자체 | Hsieh et al., **Tool Documentation Enables Zero-Shot Tool-Usage with LLMs** (arXiv:2308.00675) | 시연(few-shot demonstration) 대신 **문서(documentation)** 를 준다 | 문서만 준 zero-shot 이 few-shot 시연과 동등하거나 상회. 도구 수백 개 환경에서는 시연보다 문서가 유의하게 낫다 |
| 기법 1·2·3 (구조화·통일 인터페이스) | Yuan et al., **EASYTOOL: Enhancing LLM-based Agents with Concise Tool Instruction** (arXiv:2401.06201) | 길고 제각각인 도구 문서를 **기능 설명 + 인자 명세**의 통일된 간결 지시로 정제 | 토큰 소비를 줄이면서 도구 활용 성능 향상. "증강은 길이가 아니라 구조"의 직접적 근거 |

| V1→V2 의 재작성 루프 | Guo, Dong, Gao, Das, **Learning to Rewrite Tool Descriptions for Reliable LLM-Agent Tool Use** (arXiv:2602.20426) | 사람이 쓴 모호한 설명을 에이전트용으로 **재작성**한다 (Trace-Free+ 커리큘럼) | StableToolBench(도구 150개+)에서 스케일 시 정확도 저하 **−29.23%**, 질의 단위 성공률 **+60.89%** |
| 기법 5·6 의 반복 개선 절차 | Qu et al., **From Exploration to Mastery: Enabling LLMs to Master Tools via Self-Driven Interactions** (DRAFT, arXiv:2410.08197, ICLR 2025) | 탐색 → 분석 → 재작성 3단 루프로 문서를 시행착오로 다듬는다 | 문서 품질 개선이 도구 사용 성능으로 이어짐 |
| **하지 않기로 한 것** (임베딩 사전 선별) | Gan & Sun, **RAG-MCP: Mitigating Prompt Bloat in LLM Tool Selection via RAG** (arXiv:2505.03275) | 도구 카탈로그를 검색으로 좁혀 프롬프트에 넣는다 | 도구가 많을 때 선택 정확도 향상. **이 서버는 도구가 3개**라 프롬프트 블로트가 병목이 아니어서 적용하지 않았다 |

**이 저장소가 문헌과 갈라선 두 지점**(둘 다 측정으로 정한 것이다):

1. **동의어 증강을 무제한으로 넣지 않는다.** 문헌은 검색 친화 키워드를 넉넉히 권하지만,
   여기서는 그것이 과잉호출을 0% → 25% 로 밀어 올렸다(§6.1).
2. **태스크 동사를 앞으로 빼지 않는다.** 한국어는 동사가 뒤에 온다. 어순을 뒤집으면
   문장이 부자연스러워지고, 도구가 3개라 임베딩 사전 선별을 쓰지 않으므로 이득이 없다.

## 6. 실패에서 배운 것 — 이것이 방법론의 본론이다

### 6.1 키워드 증강은 경계 명시와 **짝으로만** 넣는다

V1 이 첫 줄에 검색용 동의어("별 보여?·괜찮아?·볼 수 있어?")를 몰아 넣자
**"서울 남산타워에서 별이 잘 보일까?"까지 3/3 으로 도구를 불렀다.**

```
TSA 100.0% → 95.8%        OTR 0.0% → 25.0%
```

재현율(recall)을 올린 만큼 정밀도(precision)가 깎인 것이다. V2 가 바꾼 것은 셋뿐이다:

1. 첫 줄 키워드에 범위를 붙인다 — "**제주도 안의**" 를 앞세운다.
2. 도구마다 **`[부르지 않는 경우]`** 절. **음성 예시를 이름까지 적는다**
   (서울 · 부산 · 남산타워 / 맛집 · 숙소 · 렌터카 · 일반 상식).
3. 미등록 장소로 "확인되지 않았다"고 답할 때도 `map_url` 은 함께 옮기라는 한 줄.

이것만으로 과잉호출이 0% 로 돌아오고 V1 이 얻은 이득은 남았다.

### 6.2 도구 설명에 **답 쓰는 법**을 넣으면 도구를 안 부른다

V1 첫 판에 `[응답 작성] map_url 을 첫 줄에…` 절을 달았더니 모델이 도구를 부르지 않고
바로 답을 썼다 — **호출률 100% → 25%**.
도구 설명은 *언제 부르는가*의 자리이고, *어떻게 답하는가*는 시스템 프롬프트 자리다.

### 6.3 설명 안에 **예시 결과값**을 쓰지 않는다

형식 예시로 넣은 가짜 주소(`…/maps/ab12cd34.html`)를 모델이 답에 그대로 베꼈다.
예시는 **호출 인자까지만** 든다.

### 6.4 증강은 길이가 아니라 구조다

첫 판에서 설명 길이를 V0 의 3배로 키우자 프롬프트가 2,280 → 4,534 토큰으로 늘고
"부르라"는 신호가 묽어졌다. 최종 V1/V2 는 V0 의 약 1.5배로 맞췄다.
EASYTOOL(arXiv:2401.06201)이 "정제해서 간결하게"라고 말한 것과 같은 자리다.

## 7. V3 — 넣었다가 보류한 것

V3 은 문헌이 권하는 기법 중 아직 안 넣은 둘을 얹은 판본이다:
**오류 응답을 `verdict · 원인 · 다음 행동` 표로 구조화**, **인자 주석을 `[형식]·[범위]·[제외]`
3축으로 라벨링**.

측정 [results/ctx8192/RESULT_2026-08-24_ctx8192.md](results/ctx8192/RESULT_2026-08-24_ctx8192.md):

| 지표 | 운영(V2) | V3 |
|---|---|---|
| TSA | 91.7% | **100.0%** |
| AEM | 90.0% | **100.0%** |
| ASF1 | 0.863 | **0.931** |
| GFR | 78.1% | 49.5% |
| 지도 주소 전달 | 90.0% | 0.0% |

**gold 비의존 지표(TSA · AEM · ASF1)는 뚜렷이 좋아졌다.** 인자 3축 라벨이 먹혔다는 뜻이고,
이는 문헌의 예측과 같다.

**gold 의존 지표(GFR · 지도)는 신뢰하지 않는다.** V3 시행의 추천 목록이 정답의 목록과
통째로 다르다(정답 `영실입구 주차장 · 성판악 주차장 · 1100고지 휴게소` ↔ V3 답변
`어리목입구주차장 · 물영아리오름 · 아부오름`). 그 사이 예보가 갱신돼 **정답이 낡은 것**으로
보인다 — 규약 §11.4 가 경고한 함정을 다시 밟았다. 지도 주소 전달 0% · 위조 100% 도
같은 원인이다(`/maps/<해시>` 가 정답과 어긋난다).

**그래서 V3 은 채택하지 않았다.** 기각이 아니라 **판정 보류**다. 채택하려면
`--arm tool-floor` 로 정답을 먼저 다시 만들고 V2 · V3 을 같은 세션에서 나란히 재야 한다.

## 9. 이 실험이 말하지 못하는 것

- **모델 한 종이다.** `qwen3.5:4b` 에서 이긴 설명이 다른 모델에서도 이긴다는 보장은 없다.
  특히 이 서버의 호스트 LLM 은 100b 급이라, 4b 에서 나온 결론으로 설명을 **줄이는**
  방향의 판단은 하지 않는다.
- **케이스 24개 × 3회 = 72시행**이다. 몇 %p 차이는 유의하지 않을 수 있어 비율 지표에는
  Wilson 95% 신뢰구간을 함께 적는다 (TSA 100% → [95–100]%p, n=72).
- **채점은 규칙 기반**이라 문장 품질·설득력은 재지 않는다. 사실 일치만 본다.
- **날씨 의존 값은 측정 시점에 묶여 있다.** 정답은 반드시 같은 세션에서 만든다(§7 참조).
- **1-hop 만 본다.** 도구 2개 연쇄는 범위 밖이다.
