# 진행 상황

단계 번호는 **실제 구현 순서**다. 초기 계획서(`docs/plan.md` 이력 참조)의 번호와 다르다 —
지오코딩처럼 계획상 뒤였던 축이 먼저 들어갔고, 별 개수처럼 앞이던 축은 폐기됐다.

> **2026-08-03 개정**: 사용자를 제주 관광객으로 좁히면서 제품 정의가 바뀌었다
> (`plan.md` §0). 질문이 "이 좌표에 별이 보이나"에서 **"지금/오늘 밤, 갈 수 있는 거리 안에서
> 어디로 갈까"**로 이동했다. 완료 단계(P0~P6)는 그대로지만 **P7 이후를 전면 재구성**했다.

| **P10** | 추천 (`find_spots`) | 어둡기 + 구름 + 달빛으로 랭킹. **여기부터 시연 가능** |
| **P11** | 접근성 | 오프라인 라우팅 주행시간(정체 미고려), 주차·화장실, 카카오맵 길찾기 딥링크 |
| **P12** | 안전 | 고정 위험(급커브·무가로등·야생동물)은 순위 반영, 경로 안개는 경고 분리 |
| **P13** | 지도 HTML | 정적 HTML 생성 → `map_url` 반환. stateless 유지, Gradio 는 판정 경로에서 제외 |
| **P14** | 경로 탐색 | "숙소 가는 길에" — 경로 버퍼 탐색 |

> **P9 를 먼저 손댄 이유**: 후보 발굴이 웹검색으로 30~40곳에서 포화하는 것이 확인돼,
> 자동화 없이는 P10 이 성립하지 않는다는 게 분명해졌다. P7·P8 은 그대로 다음이다.

> 순서 근거: **P7·P8 은 지금 있는 엔진을 즉시 더 정확하게** 만든다. 후보를 200곳으로 불려도
> 판정이 틀리면 추천 전체가 틀리므로 판정 정확도를 먼저 올린다. 그다음 후보 풀(P9)을 세우고,
> 추천(P10)을 어둡기·구름만으로 먼저 동작시킨 뒤 거리·위험을 순위 기준으로 승격한다.
