# 진행 상황

단계 번호는 **실제 구현 순서**다. 초기 계획서(`docs/plan.md` 이력 참조)의 번호와 다르다 —
지오코딩처럼 계획상 뒤였던 축이 먼저 들어갔고, 별 개수처럼 앞이던 축이 뒤로 갔다.

## 완료

| 단계 | 축 | 답하는 질문 | 산출물 |
|---|---|---|---|
| **P0** | 걷는 뼈대 | (스키마만) | FastMCP stateless `/mcp`, 고정 응답 스키마, 제주 범위 가드 |
| **P1** | 시간 (박명) | "지금 하늘이 어두운가" | `core/astro.py` — DE421 태양 고도 → 박명 4단계 등급 |
| **P2** | 지명 입력 | "성산일출봉이 어디인가" | `clients/geocode.py` — Photon, `evaluate_place` 도구 |
| **P3** | 구름 | "볼 수 있나" | `clients/open_meteo.py` + `core/judge.py` — 총운량 사다리 |
| **P4** | 밤 집계 | "오늘 밤 몇 시간 볼 수 있나" | `core/tonight.py` — `scope="night"`, 관측 가능 시간·창·분포 |
| **P5** | 어둡기 (광공해) | "여기 얼마나 어두운가" | `core/darkness.py` — SB 래스터 → SQM·Falchi·은하수 문구 |
| — | 테스트 | — | `tests/` 신설. 각 모듈 `__main__` 검증 블록을 Given-When-Then 으로 이관 |

> P1~P3 은 코어 모듈이 한 커밋에 함께 들어온 뒤 단계적으로 다듬어졌다. 위 표는 **각 축이
> 실제 판정에 반영된 시점** 기준이다.

## 다음

| 단계 | 축 | 내용 |
|---|---|---|
| **P6** | 관측지 탐색 | 관측지 크롤링으로 후보 확장(현재 `jeju_spots.json` 20곳) → 어둡기 기준 랭킹 top 출력. `find_spots` 진입점 |
| **P7** | 별 개수 | 달빛 산란(K&S 1991) → 한계등급(Crumey 2014, F=2) → BSC5 별 수. "오늘 밤 별 약 N개" |

> 순서 근거: 랭킹은 지금 있는 어둡기(SQM) 축만으로도 동작한다. 데이터를 먼저 불리고,
> 별 개수는 나중에 랭킹 점수 기준으로 승격한다.
>
> 초기 계획서는 별 개수를 "핵심 완성점"으로 앞에 뒀으나, 실사용 가치가 나오는 순서로 바꿨다.
> 계획서 P2 에 묶여 있던 **달(월몰·조도)** 은 별 개수 축(P7)으로 합쳐졌다 — 달빛 계산 없이
> 월몰 시각만 내보내는 중간 단계를 두지 않기로 했다.
